# 可撤销通知关闭按钮设计

## 背景

账页在删除流水后显示“流水已删除”和“撤销”按钮，但通知没有关闭按钮。用户只有执行撤销后，才能在后续普通通知中看到关闭按钮，导致删除通知持续遮挡界面。

根因位于应用外壳的通知模板：操作按钮与关闭按钮使用互斥条件渲染。通知包含 `undo-delete` 或 `undo-save` 操作时只渲染“撤销”；没有操作时才渲染“×”。

## 目标行为

- 删除流水后显示“流水已删除”“撤销”和“×”。
- 点击“撤销”恢复被删除流水，并显示可关闭的“已撤销删除”通知。
- 点击“×”只关闭当前通知，不恢复流水，也不执行其他账本操作。
- 所有带撤销操作的通知统一同时显示操作按钮和关闭按钮。
- 通知不增加自动消失计时，避免用户失去明确的撤销机会。

## 实现边界

仅调整 `App.vue` 中通知按钮的渲染结构：撤销操作按钮继续按 `toast.action` 决定是否出现，关闭按钮改为始终出现。现有 Pinia 状态、删除与恢复逻辑、数据库行为和通知样式体系保持不变。

关闭按钮保留现有无障碍名称“关闭提示”，继续调用 `store.clearToast()`。撤销按钮继续调用对应的 `store.undoDelete()` 或 `store.undoLastSave()`。不引入新组件、计时器或全局状态。

## 状态流

1. 用户删除流水，仓库完成软删除，通知状态设为 `undo-delete`。
2. 界面同时渲染“撤销”和“×”。
3. 用户点击“撤销”时执行现有恢复流程；成功后通知变为普通“已撤销删除”提示。
4. 用户点击“×”时仅清空通知；已完成的删除保持不变。
5. 若撤销操作失败，现有错误处理继续显示错误信息，不改变本次修复范围。

## 测试

新增应用级回归测试，验证：

- 删除通知同时存在“撤销”和带“关闭提示”名称的关闭按钮。
- 点击关闭按钮会移除通知，且不会调用恢复流水仓库方法。
- 点击撤销按钮会调用恢复流水仓库方法，并显示“已撤销删除”。

## 非目标

- 不添加自动消失。
- 不改变通知位置、尺寸或视觉主题。
- 不改变删除确认弹窗、软删除机制或撤销数据逻辑。
- 不处理与通知关闭无关的界面改造。
