# 物品日均改用购买日期起算设计

日期：2026-08-21

## 目标

删除新增和编辑物品表单中的“开始使用”字段。购买日期同时代表开始使用日期，所有使用天数和日均成本统一从购买日期起算。

## 用户界面

- 物品表单只保留购买日期，不再显示或要求填写开始使用日期。
- 物品卡片显示购买日期。
- 从支出流水创建物品时，只把流水日期带入购买日期。
- 日期规则简化为 `购买日期 ≤ 当前日期`，已停用物品还需满足 `购买日期 ≤ 停用日期 ≤ 当前日期`。

## 数据兼容

- `OwnedItem.startedLocalDate` 暂时保留，确保 v1.4.0 数据库和 JSON 不需要再次改变结构。
- 新增或编辑物品时，仓储始终把 `startedLocalDate` 写成 `purchaseLocalDate`，外部保存接口不再接收独立开始日期。
- 启动 v1.4.1 时，已有物品若两个日期不同，会在事务中规范为购买日期并生成新的本地修订；不删除物品、成本或流水。
- 导入 v1.4.0 JSON 时继续接受旧的独立开始日期；恢复入库时自动规范为购买日期。
- 日均计算引擎直接使用购买日期，即使遇到尚未规范的旧内存数据也不会继续采用旧开始日期。

## 计算

`使用天数 = 结束日 - 购买日期 + 1`

使用中物品的结束日为当前本地日期；停用物品的结束日为停用日期。当天购买按 1 天计算。总成本和维修费、配件费规则不变。

## 数据影响

已有物品不会丢失。如果旧物品的开始使用日期晚于购买日期，升级后使用天数会增加，日均成本会相应降低；这是本次规则调整的预期结果。

## 测试

- 领域测试证明开始字段与购买日期不同时仍按购买日期计天。
- 仓储测试证明新增只需购买日期，保存结果中两个兼容字段相等。
- 初始化和备份恢复测试证明旧数据自动规范且不丢物品或追加成本。
- 组件和端到端测试证明“开始使用”输入已删除，新增与刷新持久化继续可用。
- 旧版固定明文和加密 JSON 兼容测试继续通过。
