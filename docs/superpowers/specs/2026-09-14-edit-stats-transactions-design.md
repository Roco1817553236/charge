# 从统计明细编辑流水设计

## 目标

统计页的小类明细当前只能查看。用户需要直接点击其中任意流水进入现有编辑流程，修正漏选或选错的分类、金额、日期、时间和备注，而不必再到“流水”页搜索。

## 交互方案

采用“整行点击后跳转到记账页”的方案：

- 小类明细中的每笔流水改为完整可点击的按钮行，保留日期、时间、备注和金额，并增加编辑提示。
- 鼠标点击、触摸、Enter 和 Space 都可进入编辑。
- 点击后跳到“记账”页并回填该流水的全部字段，复用现有 `beginEdit` 流程。
- 不在统计页复制第二套编辑表单，也不使用狭小的独立编辑图标作为唯一入口。

## 保存语义

- 保存时通过原流水 ID 调用更新操作，覆盖原记录的字段。
- 不软删除旧流水，也不新增替代流水，因此列表中始终只有一笔，物品成本等来源引用继续指向同一个 ID。
- 编辑重复检查继续生效：按收支类型、日期和金额寻找其他流水，并排除正在编辑的流水自身。
- 保存失败时停留在记账页，保留编辑草稿，原流水继续保持未修改状态。

## 返回统计

- 只有从统计明细进入编辑时，保存成功后自动返回统计页。
- StatsPage 在 SwipePager 中保持挂载，因此月度/年度、所选期间、大类、小类和展开状态继续保留。
- 如果编辑后流水不再属于原小类或当前统计期间，它会从原明细中消失；这是更新后的正确结果。
- 若原小类因数据变化已经没有有效统计行，现有监听逻辑负责关闭失效明细或选择仍存在的大类。
- 从普通流水页进入编辑时保持原行为，保存后停留在记账页。

## 组件边界

- `StatsPage`：把流水行渲染为按钮并发出 `edit` 事件，事件负载为原 `Transaction`。
- `App`：记录编辑来源是否为统计页，调用 `store.beginEdit(transaction)`，并在成功保存后决定是否把 `pageIndex` 切回统计页。
- `bookStore` 与 `LocalRepository`：继续使用现有编辑身份和 `updateTransaction`，不新增数据字段或仓储方法。

来源标记只存在于当前 App 会话中，不写入 IndexedDB、草稿或 JSON。刷新记账页后，编辑身份仍按现有机制恢复，但来源标记不会恢复；此时保存成功后留在记账页，避免持久化新的导航状态。

## 可访问性与样式

- 每行提供包含日期、分类上下文、备注和“编辑”的可访问名称。
- 使用原生 `button`，保持清晰焦点样式和至少 44 像素的触控高度。
- 编辑提示不挤压金额；长备注继续省略显示，手机宽度不得横向溢出。
- 不改变收入红、支出绿及现有大类/小类图表颜色。

## 版本与兼容

以 v1.7.0 发布。只修改界面事件和导航编排：

- IndexedDB 版本不变。
- JSON schema 不变。
- 不迁移、删除或重写任何历史流水与分类。
- README、CHANGELOG 和应用内更新说明同步更新。

## 测试与验收

- StatsPage 组件测试验证每行是按钮，点击后发出准确的原流水，键盘语义由原生按钮提供。
- App 测试验证从统计编辑会回填字段、保持原 ID 更新，并在成功后返回统计页。
- App 测试验证保存失败不返回统计，重复确认路径成功后仍返回统计。
- 回归测试验证从流水页编辑不会自动返回统计。
- Playwright 在手机宽度下完成：展开统计小类 → 点击流水 → 修改分类或备注 → 保存 → 自动返回原统计明细。
- 完整单元/组件测试、类型检查、生产构建、端到端测试、覆盖率和依赖审计通过。
