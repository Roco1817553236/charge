# 记账详情默认展开与日期自动递增设计

## 目标

优化连续补录账单：进入记账页即可填写日期、时间和备注；保存后不再总是回到今天，而是根据用户所选日期的现有流水数量决定维持原日期或进入下一天。

## 详情区域

- 记账页首次显示时，“日期、时间与备注”默认展开。
- 保留现有展开/收起按钮，用户仍可主动收起。
- 编辑或复制带备注的流水继续自动展开。
- 用户主动收起后，普通草稿更新和保存不得强制重新展开；重新加载应用时再次默认展开。

## 日期递增规则

只在成功新增流水后执行，编辑现有流水不执行。

1. 以本次实际保存的 `occurredLocalDate` 为基准。
2. 保存成功后，统计该日期下全部未删除流水；收入和支出均计入。
3. 总数少于 3 笔时，下一张空白草稿继续使用本次日期。
4. 总数达到或超过 3 笔时，下一张空白草稿使用本次日期的下一日。

示例：

- 10月1日原有 0 笔：保存第 1、2 笔后仍为 10月1日；保存第 3 笔后变为 10月2日。
- 10月1日已有 3 笔，用户从 10月2日手动改回 10月1日；保存第 4 笔后，下一张草稿再次变为 10月2日。

## 数据与异常边界

- 计数直接来自当前账本的未删除流水，不增加批次计数器或持久化状态。
- 已删除流水不计数；撤销刚保存的流水不反向修改当前草稿日期。
- 重复提醒选择“返回检查”时不变化；选择“仍然保存”且保存成功后才执行。
- 保存失败不清空草稿，也不改变日期。
- 数据库已写入但刷新失败时，使用已经回写到本机状态的保存结果计数，仍按成功保存处理。
- 编辑旧流水成功后沿用既有空白草稿行为，不根据被编辑日期递增。
- 日期按本地日历递增，正确处理月底、年底与闰年；无法再递增的最大日期保持原值。
- 不修改历史流水、分类、IndexedDB 结构或 JSON schema。

## 实现边界

- 新增纯领域函数：解析严格的 `YYYY-MM-DD`，按 UTC 日历运算得到下一天，并根据未删除流水数量计算新增成功后的草稿日期。
- `bookStore.saveEntry` 在仓储写入返回并完成本地交易列表回写后计算下一日期；只在操作期间草稿未被用户改动时重置为空白草稿。
- `emptyDraft` 支持可选日期覆盖，其余字段仍按现有规则重置；时间继续取创建空白草稿时的当前本地时间。
- `QuickEntryPage` 只负责详情区域默认展开，不承担账本计数。

## 版本与测试

以 v1.8.0 发布。测试覆盖：

- 详情默认展开且可手动收起。
- 第 1、2、3 笔的日期保持/递增边界。
- 已有 3 笔后手动返回旧日期，新增第 4 笔后再次进入下一日。
- 收入与支出共同计数、删除流水排除。
- 月底、年底、闰年和最大日期。
- 编辑、重复取消、保存失败和刷新失败路径。
- 手机端连续补录端到端流程。
