# 小类统计图高区分度配色设计

## 背景与根因

账页默认创建二级分类时，会让同一大类下的所有小类继承大类颜色。支出去向报表直接把分类保存的颜色交给环形图和右侧图例，因此多个小类虽然拥有不同金额和扇区，实际却使用同一种颜色，视觉上看起来像一整块。

本次修复只解决统计页的小类图表辨识问题，不改变分类本身的业务颜色和用户数据。

## 目标行为

- 同一大类下出现在小类统计图中的真实小类必须使用互不相同、易区分的图表颜色。
- 环形图扇区和右侧对应小类的色点必须使用同一个颜色。
- 小类颜色必须与金额排名解耦；切换月份、年度或比较口径后，同一个小类仍使用相同颜色。
- “未细分类”固定使用深灰色，“已删除小类”固定使用浅灰色，两者同时出现时仍可区分。
- 只有一个小类时仍正常显示完整圆环和 `100.0%`。
- 现有金额、百分比、排序、选择状态和大类图配色保持不变。

## 颜色分配

统计报表使用一套小类图表专用的高区分度色板。真实小类按其所属大类内的稳定顺序分配颜色：先按 `sortOrder`，再按稳定分类 ID 打破并列。颜色不依据当期金额或报表排名，因此金额变化不会导致颜色互换。

基础色板覆盖默认分类的最大二级分类数量。自定义小类超过基础色板数量时，继续按固定算法生成具有不同色相和明度的 CSS 颜色，避免简单循环色板造成重复颜色。

虚拟小类不占用真实小类的色板位置：

- `未细分类`：深灰色，表达未选择具体小类。
- `已删除小类`：浅灰色，表达历史分类已不存在。

## 数据与组件边界

颜色只存在于支出统计报表的展示结果中，不写回 IndexedDB，不改变 `Category.color`，也不触发同步、备份或数据迁移。

报表领域层负责生成稳定的小类图表颜色，并继续返回每行的 `color`。`StatsPage.vue` 保持简单：环形图和右侧图例继续读取同一个 `row.color`。大类报表仍使用大类自身保存的颜色。

这种边界可以让现有用户立即看到修复，同时保留用户在分类管理中设置的业务颜色，不给旧账本增加迁移风险。

## 兼容性与异常情况

- 已有默认小类即使保存了相同颜色，打开新版统计页后也会自动显示不同图表颜色。
- 用户自行创建或修改的小类不需要重新保存。
- 小类移动到其他大类后，按照新大类中的稳定顺序获得图表颜色，与当前报表归属规则一致。
- 归档但仍保留历史流水的小类继续使用稳定真实小类颜色；墓碑或缺失的小类使用“已删除小类”浅灰色。
- 不改变加密备份、明文备份或旧版本导入格式。

## 测试与验证

先增加失败的领域回归测试，再实现颜色分配：

- 两个保存颜色完全相同的小类进入同一报表后，返回颜色必须不同。
- 同一小类在金额排名变化后，图表颜色必须保持一致。
- “未细分类”和“已删除小类”使用不同的固定中性色。
- 小类金额、百分比及合计关系不受颜色修改影响。
- 组件继续让环形图和右侧图例读取同一组报表颜色。

## 非目标

- 不批量修改或迁移 `Category.color`。
- 不改变分类管理页面的颜色选择器。
- 不增加新的统计维度、图表类型或交互层级。
