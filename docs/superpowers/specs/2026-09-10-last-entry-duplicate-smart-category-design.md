# 首页最近记账、重复提醒与智能小类设计

## 背景与目标

本次改动优化首页快速记账流程，包含三个互相关联的能力：

1. 在首页顶部显示最近一次有效记账或编辑的时间。
2. 保存前识别同一天、同金额、同收支类型的疑似重复流水，并允许用户确认后继续保存。
3. 点击大类时自动选择一个小类；餐饮根据金额在早餐、晚餐和正餐之间自动判断。

改动不得迁移或重写历史流水、分类和备份数据，不增加服务端，也不改变现有 JSON 格式。

## 方案选择

采用轻量规则方案：最近时间和重复候选均从当前本地流水派生，小类选择规则只存在于快速记账交互层，不新增数据库字段。

没有采用以下方案：

- 为每个大类新增可配置默认小类：当前需求不需要额外设置界面和同步字段。
- 建立通用金额规则编辑器：只需要餐饮规则，通用规则引擎会显著增加复杂度。

## 最近记账时间

### 数据来源

- 只考虑当前账本中未删除的流水。
- 取 `updatedAt` 最大的一笔，因此新增和编辑都能刷新显示时间。
- 删除流水本身不算一次记账；若删除的正好是最新流水，显示时间回退到剩余流水中最新的一笔。
- 导入 JSON 后按导入流水自带的 `updatedAt` 重新计算，不写入额外元数据。

### 界面

显示在首页“记一笔”标题下方，格式为：

- 当天：`最后记账：今天 14:32`
- 昨天：`最后记账：昨天 14:32`
- 今年其他日期：`最后记账：9月8日 14:32`
- 跨年：`最后记账：2025年12月31日 14:32`
- 没有流水：`暂无记账`

显示的是本机本地时间。无效时间数据不参与计算；若所有有效流水都缺少可解析时间，则显示“暂无记账”。

## 疑似重复流水

### 匹配规则

保存新增或编辑流水前，在未删除流水中查找同时满足以下条件的记录：

- 收支类型相同；
- `amountMinor` 相同；
- `occurredLocalDate` 相同。

时间、分类、小类和备注不参与匹配。编辑流水时排除正在编辑的流水自身。

### 用户交互

- 没有匹配项时沿用当前流程直接保存。
- 有匹配项时暂停保存，显示确认弹窗。
- 弹窗说明疑似重复的笔数，并最多展示 3 笔已有流水的“分类 / 小类、金额、备注”；更多记录只显示剩余数量。
- 用户选择“返回检查”时不保存，并保留完整草稿。
- 用户选择“仍然保存”时只放行当前这一次提交，不关闭后续重复检查。
- 确认期间禁用重复提交，避免连点生成多笔流水。

重复识别只用于提醒，不会自动删除、合并或修改任何数据。

## 默认小类与餐饮金额规则

### 通用默认行为

- 点击有有效小类的大类时，立即选中按 `sortOrder` 排序后的第一个有效小类。
- 没有有效小类时保持小类为空。
- 再次点击同一大类也会重新应用默认选择。
- 切换收支类型后清空大类和小类，沿用现有行为。

### 餐饮智能选择

仅当所选支出大类的当前名称严格等于“餐饮”时启用。根据已输入金额选择当前有效且名称匹配的小类：

| 金额 | 自动小类 |
| --- | --- |
| 小于或等于 8 元 | 早餐 |
| 大于 8 元且小于或等于 13 元 | 晚餐 |
| 大于 13 元 | 正餐 |

“正餐”即本需求中的午餐，不修改分类名称。

规则在两种顺序下都生效：

- 先输入金额再点击餐饮：点击时按金额选择。
- 先点击餐饮再输入金额：金额变化时更新自动选择。

若金额为空或无效，点击餐饮时默认选择排序第一的小类，通常为早餐。

### 手动选择优先

- 用户手动点击任一小类后，该草稿进入手动选择状态；之后修改金额不得覆盖用户选择。
- 重新点击餐饮大类会恢复自动选择状态，并立即按当前金额重新判断。
- 切换到其他大类时重新采用该大类的通用默认小类。
- 保存成功并生成新草稿后，手动选择状态清空。
- 编辑或复制已有流水时保留原小类，不因金额自动重分类；只有用户主动点击大类才重新应用规则。

### 分类兼容

- 餐饮、早餐、晚餐或正餐被改名、归档、删除时，不修改用户分类，也不迁移历史流水。
- 若目标名称不存在，则退回餐饮下排序第一的有效小类。
- 导入 JSON 后直接使用其中分类；只有名称仍匹配时才启用对应餐饮规则。
- 默认分类数据不变，现有账本和新账本都不需要迁移。

## 组件与职责

- `bookStore`：提供最新有效流水时间和重复候选计算；负责在最终确认后执行一次保存。
- `QuickEntryPage`：管理自动/手动小类选择状态、餐饮金额规则以及重复确认弹窗。
- 独立领域函数：实现最近流水选择、重复匹配及餐饮小类决策，避免规则散落在模板中，并便于单元测试。
- `App`：继续传递流水、分类和草稿；不新增持久化服务或同步流程。

重复确认采用组件内状态，不写入草稿、IndexedDB 或 JSON。自动/手动小类状态同样只属于当前界面会话。

## 异常与边界处理

- 金额解析失败时不运行餐饮阈值判断，现有金额校验负责阻止保存。
- 金额采用分为单位比较，边界分别为 800 分和 1300 分，避免浮点误差。
- 已删除流水不参与最近时间或重复检测。
- 重复确认弹窗打开后若数据刷新，最终保存前仍由保存流程按当前草稿执行校验。
- 最近时间格式化失败不得阻止应用加载或记账。

## 测试与验收

### 领域测试

- 最近时间覆盖无流水、删除流水、编辑时间、跨日和无效时间。
- 重复检测覆盖同类型同日期同金额、不同类型、不同日期、不同金额、已删除和编辑排除自身。
- 餐饮金额覆盖空金额、8 元、8.01 元、13 元和 13.01 元。
- 分类缺失或归档时正确退回第一个有效小类。

### 组件与端到端测试

- 首页显示正确的最近记账文本，新增和编辑后实时刷新。
- 普通大类点击后选中第一个小类。
- 餐饮在先输金额和后输金额两种顺序下都正确选择。
- 手动选择后金额变化不覆盖，重新点击餐饮后恢复自动判断。
- 新增和编辑疑似重复流水时弹窗内容正确；返回不保存，确认只保存一次。
- 手机宽度下弹窗不溢出，键盘操作和焦点顺序可用。

### 回归验收

- JSON 导入导出结构不变。
- 现有分类和历史流水不被修改。
- 流水编辑、复制、撤销保存、删除与撤销删除保持可用。
- 全部单元测试、组件测试、构建和 Playwright 端到端测试通过。
