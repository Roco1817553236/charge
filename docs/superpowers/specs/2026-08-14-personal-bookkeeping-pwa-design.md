# 个人记账 PWA 设计规格

日期：2026-08-14

## 1. 产品目标

构建一款面向个人日常使用的轻量记账应用。应用覆盖 Windows、Android 和普通桌面/手机浏览器，不要求用户自建服务器，也不依赖付费 API 或付费数据库。核心体验是“打开应用，三步内完成一笔账”，同时提供清晰的分类统计、月度环比和年度同比。

应用采用本地优先架构：断网时完整可用，联网后把端到端加密的数据同步到用户自己的 OneDrive。应用托管方不保存用户账目，也没有持续运行的后端服务。

## 2. 成功标准

- 熟悉应用的用户可通过“金额、分类、保存”在约 3 秒内完成一笔常用支出。
- Windows、Android 和浏览器使用同一个微软账号及同步密码后，可自动合并账目。
- 断网记账、跨设备恢复联网、应用升级和分类调整均不得造成已确认账目丢失。
- 一万笔流水下，常用搜索及月度/年度报表目标在约 1 秒内完成。
- 普通功能更新无需重新下载安装。
- 用户无需绑定银行卡、开通计费账户、购买域名或维护服务器。
- 用户可随时导出完整 JSON 和 Excel 可读的 CSV，避免平台锁定。

## 3. 第一版范围

### 3.1 包含

- 手动记录支出和收入。
- 金额、大类、可选二级分类、日期、时间和备注。
- 快速记账、流水、统计三个横向页面。
- 左右滑动、底部页签、桌面触控板/鼠标拖动与页签点击。
- 流水搜索、按月/收支类型/分类筛选、编辑、复制、删除和撤销。
- 最多两级且完全可自定义的分类体系。
- 月度收支、结余、每日趋势、分类占比及二级分类下钻。
- 月度环比、年度同比、12 个月趋势、年度汇总和明确标注的年度预测。
- OneDrive 加密同步、离线队列、冲突处理和同步状态。
- 应用内更新提示、更新日志和数据库迁移保护。
- 默认加密的 JSON 备份/恢复、可选明文 JSON、CSV 导出、深色模式和人民币格式。

### 3.2 暂不包含

- 银行卡、支付宝或微信账单自动导入。
- 账户余额与账户间转账。
- 分类预算与超支提醒。
- 发票/小票识别和图片附件。
- 周期账单、多币种、借贷管理和多人共享账本。
- 广告、行为追踪和第三方分析 SDK。

上述能力可在后续版本扩展，但第一版的数据和模块边界不得阻碍这些扩展。

## 4. 交互与页面

### 4.1 页面结构

应用固定包含三个一级页面，顺序如下：

1. **记账**：每次启动默认页面。
2. **流水**：向左滑一次进入。
3. **统计**：继续向左滑进入。

底部始终显示“记账、流水、统计”三个页签。手势用于快速切换，页签用于提示当前位置和直接跳转。Windows 同时支持触控板横向手势、鼠标拖动及页签点击。

### 4.2 快速记账

- 默认类型为支出，可切换为收入。
- 金额输入获得最高视觉优先级。
- 首页显示最多六个固定/常用大类，其余分类通过“更多”展开。
- 选择大类后显示可选二级分类；不选二级分类也可保存。
- 日期时间默认当前值，备注可留空。
- 保存后展示短暂的“撤销”入口，并允许立即继续记录下一笔。
- 未保存草稿在页面切换、应用后台化或更新提示出现时保留。

### 4.3 流水

- 默认按本地日期倒序分组，显示每日支出/收入小计。
- 支持关键词、月份、收支类型、大类和二级分类组合筛选。
- 单笔记录支持编辑、复制和软删除。
- 软删除后可立即撤销；跨设备同步后仍以删除标记合并。

### 4.4 统计

- 月度主页显示支出、收入、结余、笔数、每日趋势和大类占比。
- 点击大类后下钻到二级分类。
- 月度环比显示本期与上期收支、结余和分类变化。
- 当前月份尚未结束时，标题指标默认使用“本月至今 vs 上月同期”；允许切换为完整月份比较。
- 年度同比默认使用“今年至今 vs 去年同期”，并展示 12 个月并列柱状趋势。
- 年度预测按当前已完成月份/月内进度计算，必须标注“仅供参考”。

## 5. 分类体系

分类最多两级。大类和二级分类均使用永久 UUID，而不是名称作为关联键。

用户可以：

- 新增、改名、换图标、换颜色和调整顺序。
- 将大类固定到快速记账区域。
- 新增二级分类，或将其移动到其他大类。
- 隐藏/归档已经使用的分类。
- 删除从未被流水引用的分类。
- 恢复被隐藏的系统默认分类。

移动二级分类会改变其关联流水在历史报表中的大类归属。执行前必须显示受影响的历史笔数并要求确认。已经被流水引用的分类不能物理删除，只能归档，以保证历史数据完整。

### 5.1 默认支出大类

- 餐饮：早餐、正餐、外卖、零食饮料。
- 生活缴费：水费、电费、燃气费、手机话费、宽带、物业费。
- 交通出行：公交地铁、打车、油费、停车养车。
- 购物：日用品、服饰、数码、美妆。
- 居住：房租房贷、家具家电、维修。
- 医疗健康：药品、门诊、体检、健身。
- 娱乐休闲：影音、游戏、聚会、旅行。
- 学习：图书、课程、考试。
- 人情往来：红包、礼物、孝亲。
- 其他。

默认收入分类为工资、奖金、副业、报销、理财收益、红包礼金、退款和其他；用户同样可以建立二级分类。

## 6. 技术架构

### 6.1 技术选型

- Vue 3 + TypeScript + Vite。
- Pinia 管理页面状态和未保存草稿。
- Dexie 封装 IndexedDB。
- `vite-plugin-pwa`/Workbox 提供安装、离线缓存和更新检测。
- 自有轻量 SVG/CSS 图表提供月度/年度可视化，不加载第三方 CDN，并同时提供可访问文本摘要。
- `@azure/msal-browser` 使用授权码 + PKCE 登录微软个人账号。
- Microsoft Graph 仅请求 `Files.ReadWrite.AppFolder`，访问 OneDrive 应用专属目录。
- Vitest 执行单元/集成测试，Playwright 执行端到端测试。
- 静态构建部署到公开 MIT 仓库对应的免费 GitHub Pages 子域名；不要求自定义域名。应用使用 Hash Router，避免 GitHub Pages 刷新子路由时返回 404。

### 6.2 模块边界

- **AppShell**：安装状态、三页导航、主题、全局提示。
- **EntryFeature**：草稿、金额输入、分类选择和保存反馈。
- **LedgerFeature**：流水列表、搜索、筛选、编辑和软删除。
- **CategoryFeature**：两级分类、排序、归档和移动规则。
- **ReportingEngine**：月度/年度聚合、同期比较和预测；仅接受标准化账目数据。
- **LocalRepository**：IndexedDB 读写、事务和索引；不包含 UI 逻辑。
- **CryptoVault**：密钥生成、包裹、加密、解密和完整性验证。
- **SyncEngine**：同步状态机、ETag、重试、合并、冲突记录和快照。
- **SyncProvider**：云同步接口；第一版实现 `OneDriveSyncProvider`，以后可替换其他提供方。
- **ImportExportService**：JSON 备份/恢复及 CSV 导出。
- **UpdateService**：Service Worker 更新提示、数据库版本迁移和回退保护。

模块通过类型明确的接口通信。报表不得直接访问 OneDrive，UI 不得直接操作加密文件，OneDrive 提供方不得包含分类或统计业务逻辑。

## 7. 核心数据模型

### 7.1 Transaction

- `id`: UUID。
- `type`: `expense | income`。
- `amountMinor`: 以分为单位的正整数。
- `currency`: 第一版固定 `CNY`。
- `categoryId`: 大类 UUID。
- `subcategoryId`: 可空的二级分类 UUID。
- `occurredLocalDate`: `YYYY-MM-DD`，用于月度归属。
- `occurredLocalTime`: `HH:mm`。
- `timeZone`: 记录产生时的 IANA 时区。
- `note`: 最多 500 个 Unicode 字符。
- `createdAt`、`updatedAt`: UTC 时间。
- `revision`: `{ counter, deviceId, clock }` 向量逻辑版本；`clock` 记录各已观察设备的计数器。
- `deletedAt`、`deleteRevision`: 软删除时存在。

存在 `subcategoryId` 时，该二级分类必须处于活动或归档状态，且其 `parentId` 必须等于记录的 `categoryId`。归档分类仍可显示历史记录，但不能用于新账目。

### 7.2 Category

- `id`: UUID。
- `type`: `expense | income`。
- `parentId`: 大类为 `null`；二级分类为大类 UUID。
- `name`、`icon`、`color`、`sortOrder`。
- `isPinned`: 是否固定在快速记账区域。
- `status`: `active | archived`。
- `revision`、`createdAt`、`updatedAt`。

### 7.3 其他实体

- `BookSettings`：人民币账本格式、统计偏好和其他需要跨设备一致的设置，随加密账本同步。
- `bookEpoch`：明确恢复备份时递增的账本代际；新代际整体优先于旧代际，避免旧云端/旧设备记录复活；并发恢复会停止自动覆盖并要求人工确认。
- `DeviceSettings`：主题、安装状态、是否记住解锁和本地版本，仅保存在当前设备。
- `DeviceState`：设备 ID、逻辑计数器、最近同步版本和可选的停用时间。
- `SyncMetadata`：远端 ETag、最后成功时间、待同步状态和已知设备确认点。
- `ConflictRecord`：同一记录的本地/远端候选版本及处理状态。
- `Tombstone`：删除对象和删除版本；所有未停用设备确认后且至少保留 90 天才可清理。设置页允许用户在重新验证同步密码后停用永久遗失或不再使用的设备。

v1.0 交付采用更保守的过渡策略：尚未提供设备退休和垃圾回收入口，所有墓碑永久保留。只有后续版本完整实现同步确认点、重新验证密码和设备退休修订后，才允许执行上述 90 天清理规则。

## 8. 本地与同步数据流

### 8.1 写入流程

1. 用户保存账目。
2. `EntryFeature` 校验金额和分类。
3. `LocalRepository` 在 IndexedDB 事务中写入记录并递增设备逻辑计数器。
4. UI 立即显示“本机已保存”。
5. `SyncEngine` 在短暂防抖后启动后台同步。
6. 离线或同步失败时保留待同步标记，不阻塞后续记账。

### 8.2 OneDrive 文件

OneDrive 应用目录保存：

- `vault-v1.json`：加密信封、密文和同步版本。
- `snapshots/`：最近五次成功同步前的加密快照。

同步步骤：

1. 使用远端 ETag 条件下载/上传。
2. 解密远端负载，与本地记录按 UUID 和逻辑版本合并。
3. 不冲突的新建、编辑和删除按向量时钟自动合并；不同设备的离线计数器不能仅凭数值大小互相覆盖。
4. 同一记录并发编辑，或编辑与删除并发时创建 `ConflictRecord`，保留两个候选版本。
5. 重新加密合并结果，并使用 `If-Match` 上传。
6. 遇到 ETag 冲突时重新下载、合并并按指数退避重试。

应用在保存后、启动、恢复网络、从后台返回以及用户点击“立即同步”时触发同步。

## 9. 加密与身份

- 微软登录使用 SPA 授权码 + PKCE；前端不包含客户端密钥，也不接触微软密码。
- Graph 权限限制为应用专属目录，不申请读取整个 OneDrive。
- 首次创建账本时生成随机 256 位数据加密密钥（DEK）。
- 账本负载使用 AES-256-GCM 和每次唯一的 96 位随机 IV 加密。
- 同步密码通过 PBKDF2-HMAC-SHA-256、独立 128 位盐和信封记录的迭代参数派生密钥包裹密钥；初始迭代参数为 600,000。
- 同步密码至少 10 个 Unicode 字符，并显示强度提示；不采用会鼓励固定套路的字符种类强制组合规则。
- 另生成随机 256 位恢复密钥，用于包裹同一个 DEK。恢复密钥只展示/下载给用户，不上传明文。
- 远端信封只包含 KDF 参数、两个已包裹 DEK、随机 IV、密文、模式版本和校验所需元数据。
- 用户可选择在可信设备上记住解锁状态；本地保存不可导出的 Web Crypto 密钥对象，不保存同步密码明文。
- 首次建库的恢复密钥必须先使用本机不可导出密钥加密持久化，成功后才允许上传云端账本；用户下载确认后删除该本机待确认副本。
- 待确认恢复密钥绑定云端信封稳定指纹；条件上传确认后立即转为可展示状态，上传结果不确定时在启动静默登录或下一次显式同步中用该恢复密钥解密并完整验证远端账本。只有明确的条件上传竞争失败才作废本次临时密钥；其他不匹配保留密钥并停止同步。
- 账本正文的 AES-GCM 认证数据必须绑定恢复密钥封装；任何仅替换恢复封装的远端信封，在密码、恢复密钥和可信设备会话三条解锁路径中都必须认证失败。
- 错误密码、错误恢复密钥或 GCM 完整性失败不得修改本地/远端数据。
- 所有依赖随应用打包，设置严格的 Content Security Policy，不加载第三方脚本、广告或分析代码。
- 如果微软账号无法授予 `Files.ReadWrite.AppFolder`，应用应停止云端初始化并解释原因，不得静默升级为读取整个 OneDrive 的更宽权限。

忘记同步密码且丢失恢复密钥时，密文不可恢复；首次设置和恢复密钥下载界面必须明确提示这一点。

## 10. 更新机制

- 浏览器和已安装 PWA 启动后由 Service Worker 检查静态资源更新。
- 下载完成后显示“发现新版本”，由用户点击激活；存在未保存草稿时不得刷新。
- 离线时继续运行旧版，恢复网络后再检查。
- 设置页显示版本号、更新日志和“立即检查更新”。
- 数据库迁移采用显式 `schemaVersion` 和顺序迁移函数；首个正式数据库版本为 IndexedDB v2。v1→v2 在主数据库升级前创建独立且回读验证的安全备份，升级事务内再保留一份迁移备份。
- 激活涉及数据迁移的新版本前，创建可验证的本地备份快照。
- 迁移失败时恢复旧数据库快照，并保持上一版应用缓存可启动；不得上传半迁移数据。
- 迁移成功并完成一次读写自检后，才清理上一版缓存。

v1.0 的 Workbox 配置不主动清理旧缓存；这牺牲少量空间以保留回退材料。未保存草稿或编辑态存在时，更新激活按钮直接阻止刷新，不提供绕过确认。

迁移成功后的自检核对关键表实体 ID 并执行读写验证；若仍失败，应用保持独立旧版快照并在设置页提供明文救援下载，不要求用户直接操作 IndexedDB。

常规更新不要求用户重新下载安装。只有未来改变应用分发渠道或浏览器权限模型时，才可能要求重新授权或重新安装。

## 11. 异常处理

统一同步状态为：

- `本机已保存`
- `同步中`
- `已同步`
- `需要处理`

处理规则：

- **断网**：继续本地工作，网络恢复后自动重试。
- **授权过期**：暂停同步并请求微软重新授权；不锁定本地账本。
- **同步密码错误**：不写入任何数据，允许重试或使用恢复密钥。
- **远端损坏/无法认证**：停止覆盖远端，保留本地副本并提供最近有效快照恢复。
- **并发冲突**：自动合并安全记录；不安全记录进入冲突列表。
- **OneDrive 空间或限流**：显示可理解的原因，指数退避，并提供立即导出。
- **浏览器存储不足**：阻止会造成不完整写入的操作，提示导出和清理空间。
- **更新迁移失败**：恢复快照、保留旧版并记录本地诊断信息。

日志不得包含金额、备注、分类名称、密钥、令牌或解密后的账目。

完整 JSON 备份默认使用当前账本密钥加密，恢复时需要同步密码或恢复密钥。用户可在二次确认后导出明文 JSON；CSV 始终是明文，并在下载前提示妥善保管。

## 12. 免费使用原则

- 应用静态托管，不运行自有 API 服务器。
- 同步使用用户自己的 OneDrive 应用目录。
- 不使用付费数据库、短信、邮件、AI、OCR、地图或汇率 API。
- 不购买自定义域名；使用免费托管子域名。
- 不要求用户绑定支付方式或开启云平台自动计费。
- 本地功能不依赖免费云服务持续可用。
- `SyncProvider` 可替换，且 JSON/CSV 导出保证迁移能力。

第三方平台未来可能调整政策，因此不能承诺其规则永久不变；本设计保证即使静态托管或 OneDrive 同步暂时不可用，已安装应用和本地账本仍可使用，数据也可导出。

## 13. 测试方案

### 13.1 单元测试

- 金额整数运算、输入格式和非法金额。
- 月末、年末、闰年、时区和本地日期归属。
- 大类/二级分类聚合、改名、移动和归档。
