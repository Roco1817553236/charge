# 新建账本餐饮默认小类调整设计

## 目标

仅调整新建空账本的默认餐饮小类，将“外卖”改为“晚餐”。调整后的顺序为：早餐、正餐、晚餐、零食饮料。

## 范围

- 修改默认分类种子中的一个名称，不改变分类数量、顺序、图标、颜色、固定状态或稳定 ID。
- 仅当当前浏览器的分类库为空、需要首次创建默认分类时使用新名称。
- 不增加数据库迁移、自动改名、名称别名或导入转换。
- 以补丁版本 `1.3.1` 发布，并更新 README 与更新日志。

## 数据安全与兼容性

- 已有账本不会重新播种默认分类，因此已有的“外卖”、用户自定义名称、流水和统计数据保持不变。
- 默认分类规范化逻辑必须把名称不同的分类视为用户可见修改并保留，不能把旧账本中的“外卖”自动改为“晚餐”。
- JSON 备份中的分类是账本快照的一部分。导入时保留备份内的分类 ID 和名称，因此旧备份中的“外卖”和新备份中的“晚餐”均可正常导入。
- 流水通过分类 ID 关联，不删除、不重建、不重新分配任何已有分类或流水。
- 本次修改不改变 JSON `schemaVersion` 或 IndexedDB 结构版本。

## 实现

在 `src/domain/categories.ts` 的餐饮默认种子中，将第三个小类从“外卖”替换为“晚餐”。不修改 `LocalRepository.initialize`、导入解析器或数据库迁移代码。

## 验证

- 默认分类测试精确断言新建账本的餐饮小类为“早餐、正餐、晚餐、零食饮料”。
- 规范化测试构造旧版默认分类并断言“外卖”保持不变，以证明现有账本不会被自动改名。
- 导入测试分别验证包含“外卖”和“晚餐”的 JSON 都按原名称恢复。
- 运行单元测试、类型检查、生产构建和端到端测试。

完成代码审查后推送功能分支，创建拉取请求并合并到 `main`，随后确认 GitHub Pages 部署成功。
