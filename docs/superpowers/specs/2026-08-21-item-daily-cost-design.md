# 物品日均成本功能设计

日期：2026-08-21

## 1. 目标

在账页中增加独立的“物品”模块，用购买价格、维修费和配件费计算物品在实际使用时间内的日均成本，帮助用户判断长期使用价值。模块继续遵循完全本地、免费、离线可用和 JSON 可迁移原则，不引入服务器、账号、付费 API 或第三方分析。

本功能不是会计折旧，也不估算市场残值。核心公式为：

`日均成本 =（购买价格 + 有效维修费 + 有效配件费）÷ 实际使用天数`

## 2. 已确认范围

- 在“记账、流水、统计”之后增加第四个一级页面“物品”，支持底部页签和左右滑动。
- 物品可以从已有支出流水创建，也可以手动添加。
- 维修费、配件费作为可追溯的追加成本记录；同样支持关联已有支出或手动添加。
- 物品分类与记账分类完全独立，并支持后续自定义。
- 物品停用后，以停用日期冻结使用天数和日均成本。
- 不记录卖出金额，不扣除残值或回收收入。
- 第一版不保存物品照片，仅使用分类图标或用户选择的 Emoji，避免 JSON 备份过大。
- 采用已确认的单页展开方案：列表卡片在当前页面展开成本明细，不进入需要返回的独立详情页。

## 3. 页面与交互

### 3.1 第四页导航

`SwipePager` 扩展为四页，顺序固定为“记账、流水、统计、物品”，页面索引限制调整为 `0..3`。底部导航改为四等分；现有三个页面的顺序、默认首页和数据不变。

### 3.2 物品页

默认显示“使用中”物品，页面从上到下包括：

1. 标题与独立物品分类管理入口。
2. 汇总区：总投入成本、当前总日均、物品数量、最高日均、最低日均。
3. 筛选区：使用中/已停用/全部、物品分类、日均高低或购入时间排序。
4. 物品卡片列表。
5. 右下角新增按钮。

汇总指标跟随状态和分类筛选，排序不影响汇总。没有匹配物品时显示空状态，最高和最低日均显示“—”。金额统一按人民币和“分”存储，界面日均显示两位小数。

### 3.3 物品卡片

收起状态显示：图标、名称、总成本、日均成本、开始使用日期和实际使用天数。点击后在卡片下方展开：

- 购买价格。
- 按日期排列的维修费和配件费记录。
- 总成本。
- “追加成本、编辑、停用”操作。

同一时间最多展开一件物品。再次点击当前卡片会收起。已停用物品显示停用日期，并把“停用”替换为“恢复使用”；恢复后从原开始日期连续计天，不记录暂停区间。

### 3.4 新增物品

点击“＋”先选择来源：

- **从支出流水创建**：选择一笔支出，自动带入购买金额、购买日期和备注；用户补充物品名称、独立分类、图标和开始使用日期。
- **手动添加**：填写名称、购买金额、购买日期、开始使用日期、独立分类、图标和可选备注。

开始使用日期默认等于购买日期，但允许修改。购买金额允许为 0，适配赠品或无法确认价格的旧物；界面明确显示为 ¥0.00。必须满足 `购买日期 ≤ 开始使用日期 ≤ 当前本地日期`；未来日期、空名称或顺序错误时阻止保存并在表单内解释原因。

同一笔支出可能包含多件物品，因此允许被多次引用；再次选择时提示已经关联的物品数量，但不强制阻止。关联仅用于追溯，不修改原流水，也不会在统计中重复产生支出。

### 3.5 追加成本

“追加成本”先选择维修费或配件费，再选择关联已有支出或手动填写。每条记录包含金额、发生日期和备注；金额必须大于 0。发生日期必须在购买日期至当前日期之间；物品已停用时不得晚于停用日期。关联支出时自动带入金额、日期和备注，用户可以在保存前调整。

删除追加成本采用软删除并提供立即撤销；删除后该金额不再参与总成本和日均成本。原流水被删除时，物品成本记录仍保留，并显示“来源流水已删除”，避免资产数据跟随账单误删。

### 3.6 停用与删除

停用日期默认为当天，必须不早于开始使用日期。停用后日均成本固定；恢复使用会清除停用日期并继续按原开始日期计算。停用、恢复和删除都提供可关闭的撤销提示。

删除物品采用软删除，同时保留其追加成本以支持撤销和 JSON 恢复。已删除物品不参与列表和汇总。

## 4. 计算规则

所有日期运算使用本地日历日期，不使用毫秒除法，避免夏令时和时区造成一天偏差。

- 使用中结束日：当前本地日期。
- 已停用结束日：停用日期。
- 实际使用天数：`结束日 - 开始使用日 + 1`，因此当天开始使用按 1 天计算，不会除以 0。
- 总成本：购买金额加全部未删除的维修费和配件费。
- 单件日均：总成本除以实际使用天数，展示时四舍五入为两位小数；内部汇总使用整数金额和未提前舍入的比值。
- 当前总日均：筛选结果中每件物品未提前舍入的日均之和，最终显示时再四舍五入。
- 最高/最低日均：筛选结果中单件物品的日均极值；零成本物品按 ¥0.00/天参与比较。

## 5. 数据模型

### 5.1 ItemCategory

- `id`：稳定 UUID。
- `name`、`icon`、`color`、`sortOrder`。
- `status`：`active | archived`。
- `revision`、`createdAt`、`updatedAt`、可选软删除字段。

首次创建物品模块时提供“数码、家电、家居、工具、服饰、运动、其他”等默认分类。已有物品引用的分类只能归档，不能物理删除。

### 5.2 OwnedItem

- `id`：UUID。
- `categoryId`：独立物品分类 UUID。
- `name`、`icon`、`note`。
- `purchaseAmountMinor`：购买金额，人民币分，允许 0。
- `purchaseLocalDate`：购买日期。
- `startedLocalDate`：开始使用日期。
- `retiredLocalDate`：可选停用日期。
- `sourceTransactionId`：可选来源支出 UUID。
- `revision`、`createdAt`、`updatedAt`、软删除字段。

日均、使用天数和总成本均为派生值，不写入数据库，避免跨日期后产生过期缓存。

### 5.3 ItemCost

- `id`、`itemId`。
- `type`：`repair | accessory`。
- `amountMinor`：大于 0 的人民币分。
- `occurredLocalDate`、`note`。
- `sourceTransactionId`：可选来源支出 UUID。
- `revision`、`createdAt`、`updatedAt`、软删除字段。

## 6. 本地数据库与备份兼容

IndexedDB 升级到下一版本并增加 `itemCategories`、`items` 和 `itemCosts` 表。升级前必须在独立安全数据库中保存并回读验证现有 v2 账本快照；升级事务只新增表和默认物品分类，不修改流水、记账分类或统计设置。升级自检失败时保留救援备份入口。

JSON 账本结构升级为新版本，并包含三个新数组。兼容规则：

- 旧版 JSON 没有物品字段时，导入为“无物品 + 默认物品分类”，原流水、分类和设置保持不变。
- 新版明文和加密 JSON 必须完整往返物品、物品分类、追加成本及来源引用。
- 导入严格验证金额、日期、分类关系、物品关系和来源流水类型；软删除的来源支出仍可被引用。
- 恢复备份继续整体替换当前本地账本，不做隐式合并。
- 新实体纳入 16 MiB 文件上限和现有 AES-256-GCM 加密流程，不新增网络请求。

## 7. 模块边界

- `ItemCostEngine`：纯函数日期计算、总成本和筛选汇总，不访问数据库或 UI。
- `ItemRepository`：三个新表的事务读写、引用校验、软删除和恢复。
- `ItemStore`：页面状态、筛选、展开项、表单和提示。
- `ItemPage`：第四页展示与交互，不直接操作 IndexedDB。
- `ImportExportService`：新旧 JSON 结构适配和完整性验证。

来源流水只是可选引用。修改或删除物品不会修改流水；编辑流水也不会自动重写已经保存的物品金额，避免两个模块相互产生隐式副作用。

## 8. 异常与边界

- 购买、开始使用、追加成本或停用日期不满足上述顺序时不写入任何数据。
- 来源流水不存在、不是支出或已被彻底移除时，新增关联操作失败；已保存记录遇到软删除来源时仍可显示。
- 物品分类归档后历史物品继续显示，但不能用于新物品。
- 删除有物品引用的分类只允许归档。
- 追加成本保存失败时保持表单内容，避免用户重新输入。
- 页面跨午夜停留时刷新当前日期和日均显示，不要求重新打开应用。

## 9. 测试与验收

- 单元测试覆盖当天计 1 天、跨月/年、闰年、停用、恢复、零成本、追加成本、软删除和最终舍入。
- 数据库测试覆盖 v2→新版本升级、迁移前备份回读、现有账本不变和新表初始化。
- JSON 测试覆盖旧版导入、新版明文/加密往返、损坏关系拒绝和文件大小限制。
- 组件测试覆盖四页导航、筛选排序、卡片单项展开、追加成本入口、停用/恢复和空状态。
- 端到端测试覆盖手动新增、从流水创建、追加维修/配件费、跨午夜刷新、停用冻结和备份恢复。
- 360、736 和 1024 像素宽度下不得横向溢出；明暗主题、键盘操作、可见焦点和屏幕阅读器标签必须可用。

- [Snipe-IT 折旧模型](https://snipe-it.readme.io/docs/depreciation-types)：用于区分企业会计折旧与本功能的生活成本观察；不引入其复杂折旧算法。

## 11. 不在本次范围

- 物品照片、条形码、序列号、保修提醒和云端附件。
- 卖出收入、残值、市场估值、税务或企业会计折旧。
- 多段暂停使用、按实际小时/次数计算成本。
- 自动识别订单、小票或电商购买记录。
- 多人共享物品库或在线同步。
