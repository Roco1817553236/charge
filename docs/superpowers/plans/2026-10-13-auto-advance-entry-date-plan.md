# 记账详情默认展开与日期自动递增实施计划

设计依据：`docs/superpowers/specs/2026-10-13-auto-advance-entry-date-design.md`

## 目标版本

v1.8.0。调整记账页默认展开状态和新增成功后的空白草稿日期，不改变数据库及 JSON。

## 实施顺序

### 1. 日期纯函数

- 先新增领域失败测试，覆盖少于 3 笔、达到 3 笔、超过 3 笔、收入/支出、删除流水、月底、年底、闰年和最大日期。
- 实现严格本地日期递增和下一草稿日期计算函数。

### 2. Store 保存编排

- 先扩展 `bookStore` 测试，覆盖连续新增 1/2/3 笔、已有三笔后返回旧日期、编辑不递增、失败不改变日期及刷新失败。
- 修改 `emptyDraft` 和 `saveEntry`，在新增成功并回写本地列表后设置下一草稿日期。
- 保持现有异步草稿保护和同 ID 编辑逻辑。

### 3. 默认展开交互

- 先扩展 QuickEntryPage 测试，要求首次渲染即可看到日期、时间与备注，并验证仍可主动收起。
- 将详情初始状态改为展开，保留现有按钮和动画。

### 4. 端到端、版本与文档

- 扩展 Playwright，验证手机端手动选择历史日期，连续新增三笔后进入下一日，再改回旧日期新增后再次进入下一日。
- 更新 package、环境示例、README、CHANGELOG 和应用内更新说明到 v1.8.0。

### 5. 验证与发布

- 运行完整测试、类型检查、构建、端到端、覆盖率和依赖审计。
- 独立代码审查后修复所有 Critical/Important。
- 推送、合并 PR、等待 Pages 部署并核对线上资源。

## 约束

- 每项生产行为先有失败测试。
- 只在新增成功后递增；编辑和失败路径不递增。
- 使用账本实际未删除流水计数，不保存独立计数器。
