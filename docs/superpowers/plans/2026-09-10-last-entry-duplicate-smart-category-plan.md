# 首页最近记账、重复提醒与智能小类实施计划

设计依据：`docs/superpowers/specs/2026-09-10-last-entry-duplicate-smart-category-design.md`

## 目标版本

v1.6.0。保持完全本地、JSON 格式不变、历史流水与分类不迁移，并通过 GitHub Pages 无缝更新。

## 实施顺序

### 1. 领域规则

- 先新增 `tests/domain/quickEntry.test.ts` 失败测试，覆盖最近流水、重复匹配和餐饮金额边界。
- 新建 `src/domain/quickEntry.ts`，实现无副作用的最近时间选择、重复候选筛选、默认小类和餐饮智能选择函数。
- 以分为单位比较 800/1300 边界，并对改名、归档和删除分类安全降级。
- 运行定向测试，确认先红后绿。

### 2. Store 保存编排

- 先扩展 `tests/stores/bookStore.test.ts` 失败测试，覆盖新增/编辑的重复预检、编辑排除自身、确认后只保存一次，以及保存后实时刷新最近时间。
- 扩展 `bookStore`，提供派生的最近记账时间和重复候选，并把“预检”与“确认提交”分开。
- 保持仓储接口、IndexedDB 表结构和 JSON 快照不变。

### 3. 快速记账交互

- 先扩展 `tests/components/QuickEntryPage.test.ts` 失败测试，覆盖普通大类默认第一小类、餐饮先输/后输金额、手动选择优先、重新点击恢复自动及编辑/复制不被自动覆盖。
- 修改 `QuickEntryPage` 的小类选择状态和金额监听，只在当前草稿处于自动选择模式时应用餐饮规则。
- 为最近记账文案增加明确、可测试的属性，放在首页标题下方。

### 4. 重复确认弹窗

- 先扩展 `tests/App.test.ts` 失败测试，覆盖疑似重复信息、返回保留草稿、仍然保存和防连点。
- 在 App 层连接重复预检和确认状态，弹窗最多展示 3 笔分类、小类、金额和备注。
- 使用可访问的对话框语义、焦点管理和手机端不溢出的响应式样式。

### 5. 版本与回归

- 将应用升级到 v1.6.0，更新 `package.json`、锁文件、应用回退版本、`README.md` 和 `CHANGELOG.md`。
- 扩展 `e2e/app.spec.ts`，验证首页时间、默认/智能小类、重复返回与确认路径。
- 运行完整单元/组件测试、类型检查、构建、Playwright、覆盖率和高危依赖审计。

### 6. 审查与发布

- 使用独立代码审查检查时间格式、重复误判、手动选择优先、导入兼容和移动端弹窗。
- 修复全部 Critical/Important 问题并重新运行相关验证。
- 推送功能分支，创建并合并 PR，等待 GitHub Actions 与 Pages 部署完成。
- 在线核验 v1.6.0 资源和 PWA 更新入口。

## 约束

- 每个生产行为先有能正确失败的测试，再写最小实现。
- 不新增数据库字段、表、网络请求或远程服务。
- 不修改已有分类名称、历史流水或 JSON schema。
- 重复识别只提醒，不自动删除、合并或禁止用户继续保存。
