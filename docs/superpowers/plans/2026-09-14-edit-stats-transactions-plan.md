# 从统计明细编辑流水实施计划

设计依据：`docs/superpowers/specs/2026-09-14-edit-stats-transactions-design.md`

## 目标版本

v1.7.0。复用现有同 ID 编辑流程，从统计明细快速进入编辑并在成功后返回原统计位置，不修改数据库或 JSON。

## 实施顺序

### 1. StatsPage 编辑入口

- 先扩展 `tests/components/StatsPage.test.ts`，要求详细流水使用原生按钮并发出带原 `Transaction` 的 `edit` 事件。
- 修改 `StatsPage.vue` 的事件定义、可访问名称和响应式按钮样式。
- 运行定向组件测试，确认先红后绿。

### 2. App 编辑来源与返回

- 先扩展 `tests/App.test.ts`，覆盖统计来源标记、字段回填、成功保存返回统计、失败保留编辑页，以及普通流水编辑不改变行为。
- 在 `App.vue` 增加仅内存存在的编辑来源状态和两个入口处理函数。
- 普通保存及重复确认保存都通过统一的成功回调决定是否返回统计。

### 3. 浏览器回归

- 扩展 `e2e/app.spec.ts`，在手机宽度完成统计明细点击、编辑、同 ID 覆盖和自动返回。
- 验证长备注、金额和编辑提示不溢出，键盘可进入编辑。

### 4. 版本与文档

- 更新 `package.json`、锁文件、`.env.example`、应用回退版本、README、CHANGELOG 和设置页更新内容到 v1.7.0。
- 保持 IndexedDB 与 JSON schema 不变。

### 5. 验证、审查与发布

- 运行完整测试、类型检查、构建、Playwright、覆盖率和依赖审计。
- 进行独立代码审查，修复全部 Critical/Important 问题。
- 推送分支、创建并合并 PR、等待 GitHub Pages 成功部署，再核对线上 v1.7.0 资源。

## 约束

- 每项生产行为先有能正确失败的测试，再写最小实现。
- 更新原流水 ID，不用“删除后新增”模拟编辑。
- 不复制编辑表单，不持久化统计返回标记。
